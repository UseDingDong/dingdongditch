# Governance

DingDongDitch currently uses a maintainer-led governance model appropriate for
an early-stage project.

Maintainers set project direction, review contributions, manage releases, and
enforce community policies. Decisions prioritize the documented engineering
principles, non-goals, security boundaries, backward compatibility, and
evidence from tests and real browser behavior. No roadmap item or proposal is
a commitment until it is accepted and scheduled by a maintainer.

Routine decisions may be made in issues and pull requests. Significant changes
to public contracts, architecture, project scope, security posture, or
governance should be proposed in a public design thread (preferably a GitHub
Discussion) before implementation and recorded in durable project
documentation when accepted.

Commit access is granted at maintainer discretion based on sustained,
constructive contributions and sound judgment. This document may evolve as the
maintainer group grows; changes require maintainer approval and should be
announced publicly.
